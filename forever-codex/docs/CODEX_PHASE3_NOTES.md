# Forever Codex Phase 3: the player-facing build (0.2 alpha)

Built on the Planner (Phases 1-2.5), which is **unchanged**: `tests/golden/engine_plan.golden` (the pre-migration engine)
and the new `tests/golden/planner_eval_baseline.txt` (every Phase 2.5 evaluation decision, generated from the Phase 2.5
code and byte-identical today) both pass. Phase 3 only *consumes* the plan.

## Layers

```
Context -> Providers -> Engine.Candidates -> Planner -> plan (now / alsoDo / thenAction / reminders / diag)
                                                         |
     Presenter ---- the window (Codex page)              +-- Navigation (waypoint follows NOW)
     World, Journey, Knowledge, Party, HelpCodex pages   +-- Markers (gated, off by default)
     Telemetry observes independently                    +-- Party / Journey (observe the context)
```

| Module | Role | Files |
|---|---|---|
| Presenter | plan -> plain-language card; no ids, coordinates, sources, scores | `Presenter.lua` |
| Navigation | the game's user waypoint follows NOW; owns only its own pin | `Navigation.lua` |
| Markers | which NPC would carry star / diamond / triangle / moon; placement gated | `Markers.lua` |
| Journey | per-character history of what Codex actually saw | `Journey.lua` |
| Knowledge | human quest states; honest "unknown" for trainers, recipes, pets, flight paths | `Knowledge.lua` |
| World | what the data and quest log say about the current zone (a list, not a map) | `World.lua` |
| Party | your progress, shared and received; setting off / ui / party / both | `Party.lua` |
| HelpCodex | "Codex learns from your adventures": counts from the existing Telemetry store | `HelpCodex.lua` |
| UI | shell + pages (Codex, World, Journey, Appendices, Setup/Settings) | `UI/Main.lua`, `UI/Page*.lua` |
| DevUI | the old engineering window, now `/codex dev` | `UI/Window.lua` |

Prerequisite done first: `Planner.Compute` was split into stage functions (largest function 204 -> 41 locals) with
identical decisions (the evaluation report regenerated byte for byte).

## Player-facing now

- Compact window with NOW (star), ALSO DO (diamond, only when the Planner has one), a one-line THEN (omitted when far or
  uninformative), objective progress like `4 / 6`, a human distance word, a one-line reason. No coordinates, source,
  provenance, ids, scores, "waiting", or technical state anywhere (a test scans every text on every page).
- Show on Map, Skip, Add quest and Refresh are gone from the player window (still in `/codex dev`, and `/codex skip|add`).
- First-run setup ("Here's your character": route zone, style, systems), then hidden; Settings under Appendices.
- Automatic waypoint following NOW (setting: on by default).
- World / Journey / Appendices (Quests lookup, Knowledge, Settings, Help Improve Codex, Party).
- Window position remembered; setup remembered; per-character.
- Quiet login: one welcome line until setup is done. Engineering detail is `/codex diag` (now also reports navigation,
  party and markers state).

## Rules the implementation follows

- **Navigation ownership.** Codex remembers what it placed; a waypoint is "its own" only while the game reads back exactly
  that. It never overwrites or clears anything else, places only when NOW changes (no per-frame loop; the one-second tick
  only measures arrival), measures arrival with its own distance (20 yd, a design value) and not `C_Navigation.GetDistance`,
  does not fight the player if its pin is removed (quiet for that action), and pauses if the player has a pin of their own.
- **Unknown stays unknown.** Trainers, recipes, pets and flight paths are shown as "Codex cannot yet see ..." (their client APIs
  are unverified on Forever). Quests Codex has no location for are listed as reminders, never as destinations.
- **No identity stored.** Party member names live in memory for the session only; messages carry quest ids and numbers.
- **No upload, no export** anywhere. Help Improve Codex is local-only.
- **Questie** is a concept reference only (quest notes, journey, party awareness, settings). No code, data, UI or assets used.

## Experimental or stubbed (be explicit)

| Piece | State |
|---|---|
| World markers | Computation of *what* to mark is real and tested. **Placement is off** until `/codex markers probe` (target an NPC) proves `SetRaidTarget` works on Forever *and* the player switches markers on. Raid-target icons act on units, not map points; markers can only be set on an NPC while it is your target/mouseover. Moon (inn) is never set: there is no inn data. |
| Party sharing | Uses `C_ChatInfo` addon messages and `SendChatMessage` to PARTY: **unverified on Forever**. Feature-checked; if absent Codex still detects your own progress and has nobody to tell. Party members' own quest logs are not readable by the base client, so progress is shown only for members who also run Codex. |
| Codex arrow | Not integrated: M8.14 real-client results are still outstanding. The game's waypoint is the navigation. |
| Knowledge | Quest states are real. Trainers/recipes/pets/flight paths: honestly unknown. `IsQuestFlaggedCompleted` (behind "You did this" and the planner's completed filter) is still **unverified** at startup on Forever. |
| World tab | A list, not a map. A Questie-like map is later work. |
| Journey | Records the level Codex first saw and every turn-in it saw. It cannot list quests done before Codex was installed. |
| Window | Fixed compact size (400x360), movable, position saved. Not resizable (resize APIs unverified). Icons are coloured squares with an ASCII letter (glyphs render as boxes on Forever). |
| Login/startup protected-action message | **Still unresolved and unchanged**: "ForeverCodex has been blocked from an action only available to the Blizzard UI" was seen at first login in the 0.1 playtest; its cause is not identified. Phase 3 uses no secure frames, no protected calls, and wraps every client call; whether the message persists must be checked on the real client. |

## Tests (stub client)

`tests/phase3_tests.lua`: Presenter wording and leaks, window / setup / persistence, Journey, Knowledge, World,
Appendices, navigation ownership (own pin, foreign pin, replaced pin, removed pin, arrival, switches, login adoption,
missing API), markers (rules, gating, probe, lifecycle), party (modes, throttle, receive, caps, no identity, missing API),
Help Improve Codex, events, slash commands, diagnostics, and that NOW / ALSO DO / THEN equal the Planner alone.
Existing assertions were not weakened. A few were changed *deliberately* because the intended behaviour changed (listed in the
commit message): the developer-window checks now use `/codex dev`; the "no Navigation / Markers module" checks became "no Quest
Map module yet" (the Planner independence check is separate and unchanged); the login line check moved to `/codex diag`.
